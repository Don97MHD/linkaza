# معاينة سوق المواقع ومراجعة أولية للداشبورد

## ما تم تنفيذه محلياً

معاينة عربية/إنكليزية على الرئيسية وصفحة سوق المواقع تعرض خمس فرص توضيحية بهيئة جدول مستوحى من شاشة التطبيق. تتضمن التخصص، الدولة واللغة، مؤشر AS، الزيارات التقديرية، وبقاء الرابط. البحث والفلاتر يعملان على بيانات المعاينة فقط. تمرير القائمة داخل إطارها أو الضغط على «اكشف العرض» يفتح حوار دخول مع رابطَي التسجيل والدخول إلى `app.linkaza.com`. لا توجد حقول كلمة مرور على موقع التسويق.

الرابط المعروض في الصفوف سلسلة رموز (`••••••••.•••`) لا نسخة من رابط حقيقي مموهة بـCSS؛ لا توجد أسماء نطاقات للناشرين أو روابطها أو معرّفاتها في HTML أو حالة React أو بيانات الصفوف. الأرقام نفسها **توضيحية وليست عرضاً أو تسعيراً حقيقياً**. لا يُستخدم iframe للتطبيق، لأن إخفاء محتواه بصرياً لا يمنع كشفه عبر أدوات المطور أو الشبكة.

## الربط الآمن لاحقاً بمخزون حقيقي

واجهة التطبيق الحالية تطلب `customer/media/filter` باستخدام Bearer token خاص بالمستخدم وتعيد حقولاً بينها `url`. لا يجوز استدعاؤها مباشرة من موقع التسويق أو تمرير استجابتها كاملة ثم إخفاء الرابط في الواجهة. يلزم endpoint عام منفصل على الخادم ينتقي خمس فرص بموافقة الفريق التجاري، ويُرجع **فقط** حقولاً مُعمّمة مثل الفئة، نطاق بلد واسع، نطاق AS والزيارات، واللغة؛ لا يُرجع `url` أو `id` الأصلي أو ملاحظات فريدة أو حقولاً قد تكشف هوية الناشر بالربط. يُراجع تمييز الروابط المدفوعة (`sponsored`/`nofollow`) وشروط النشر قبل عرض أي وصف حقيقي. يجب وضع حدود للطلبات، ومراجعة الخصوصية والتخزين المؤقت، واختبار الاستجابة وملفات JavaScript وHTML والشبكة للتأكد من خلوها من الروابط المحجوبة.

## مشاكل محتملة مؤكدة من قراءة كود التطبيق المحلي

المجلد `C:\work\app-backlink.iwings-digital.com` نظيف على فرع `ali` ويشير إلى مستودع GitLab المذكور. هذه مراجعة ثابتة للكود، لا اختبار تشغيل؛ لم أعدّل ملفات الداشبورد ولم تكن تبعيات `node_modules` مثبتة عند الفحص.

1. **فشل طلب الشراء قد يغلق النافذة كما لو نجح:** `store/useOrderStore.ts` يلتقط خطأ `addNewOrder` ويعرض toast دون إعادة رمي الخطأ أو إرجاع نتيجة فشل، ثم `components/home/table/TdType/Actions.vue` يغلق حوار الشراء ويمسح حقوله بعد `await addOrder` دائماً. المطلوب إرجاع نجاح/فشل صريح وإبقاء الحوار مفتوحاً عند الفشل.
2. **بحث الجدول مربوط بمتغير غير معرّف:** القالب في `components/home/TableWithControls.vue` يستعمل `v-model="name"`، بينما المتغير المعرّف هو `searchFilterText`. لذلك قد لا تعمل قيمة البحث ولا فلتر `url` كما هو مقصود. وبعد إصلاح الاسم يجب إزالة أحد محفّزَي الجلب (`watch` أو `@update:model-value`) لتجنب طلبين لكل إدخال، مع debounce مناسب.
3. **حالة التحميل محسوبة للقراءة فقط ويجري الكتابة إليها:** `loadingData = computed(() => mediaStore.loading)` ثم تُسند `loadingData.value = true/false` في `UpdateDate`. مصدر الحقيقة ينبغي أن يبقى حالة Pinia التي تضبطها `fetchData`، أو يُستخدم `ref` مستقل إذا لزم.
4. **تعطّل محتمل عند فشل جلب الوسائط:** `fetchData` يمكن أن يترك `data = null`، بينما `totalPages` و`totalCount` يقرآن `mediaStore.data.data` دون حراسة. صفحة `pages/index.vue` تُظهر الجدول بمجرد انتهاء `pending` حتى بعد الفشل. يلزم عرض حالة خطأ/إعادة محاولة واستخدام قيم افتراضية آمنة.
5. **عناوين الأعمدة قد تبقى باللغة القديمة:** صفحة `pages/index.vue` تُعيد بناء `columns` عند تبديل اللغة، لكن `TableWithControls.vue` ينسخها مرة واحدة إلى `visibleColumns` ولا يراقب تغيّر `props.columns`. يلزم فصل مفاتيح الإظهار عن التسميات المترجمة أو مزامنة الخصائص.
6. **جلسة التطبيق تحتاج مراجعة أمنية:** Bearer token محفوظ عبر `useCookie('token')` ويُقرأ في كود العميل للطلبات. هذا يجعل الرمز متاحاً لـJavaScript في الصفحة؛ يوصى بمراجعة تصميم الجلسة والانتقال إلى كوكي `HttpOnly` مع BFF/خادم وسيط إن كان ذلك متوافقاً مع الـAPI، مع تدقيق XSS وCSRF.
7. **مصدر API مثبت في الكود:** عناوين `https://backlink.iwings-digital.com/` مكررة في المتاجر رغم وجود `runtimeConfig.public.apiBaseUrl` في إعداد Nuxt. هذا يصعّب فصل بيئات التطوير والمعاينة والإنتاج.

الخطوة التالية للداشبورد: تثبيت التبعيات في بيئة معزولة، تشغيل typecheck/lint واختبارات رحلات البحث والشراء واللغة مع حساب تجريبي، ثم ترتيب الإصلاحات. لا تُرسل مفاتيح أو رموز دخول في التقرير أو المستودع.
